Claude Code 환경을 목적에 맞게 바꾸는 Ultra Config 모드

10월 20, 2026 · 5 분 · Junho Lee

Claude Code로 짧은 스크립트를 고칠 때와 복잡한 리팩토링을 진행할 때는 원하는 작업 방식이 다릅니다. 반복 작업에서는 답변과 확인 절차를 줄이고 싶지만 원인을 알 수 없는 오류를 분석할 때는 더 충분한 추론과 설명이 필요할 수 있습니다. 다른 사람이 관리하는 저장소에서는 수정 내용을 하나씩 확인하고 싶을 때도 있습니다.

Ultra Config 는 이런 작업 방식에 맞춰 여러 설정을 한 번에 바꾸는 Claude Code용 Mod입니다. Daniel San이 만든 claude-code-templates 프로젝트에서 제공하며 다섯 가지 프로필을 선택하면 모델·추론 강도·출력 방식·승인 관련 설정을 묶어서 적용합니다.

아래에서는 제작자의 소개 글 과 프로젝트 README 를 바탕으로 각 프로필의 용도와 사용 흐름을 정리했습니다. 직접 실행해 비용 절감이나 품질 향상을 측정한 사용기는 아닙니다.

프로필을 선택하면 무엇이 달라질까#

Ultra Config의 프로필 은 작업 목적에 맞춰 미리 묶어 둔 설정 목록입니다. 예를 들어 Token Saver는 Sonnet 모델과 낮은 추론 강도, 짧은 답변을 조합하고 Max Quality는 사용할 수 있는 가장 성능 높은 모델과 높은 추론 강도를 선택하는 방향입니다.

여기서 추론 강도(effort) 는 모델이 답을 만들 때 추론에 들이는 노력을 조절하는 설정입니다. 높게 설정하면 복잡한 문제를 검토하는 데 도움이 될 수 있지만 모든 작업에서 더 좋은 결과를 보장하는 것은 아닙니다. 간단한 수정에도 항상 최대 설정을 쓸 필요는 없습니다.

설정 화면에서는 프로필을 적용하기 전에 기존 값과 바뀔 값, 변경 이유를 확인할 수 있습니다. 따라서 이름만 보고 선택하기보다 이번 작업에서 어떤 항목을 바꾸려는지 살펴보는 것이 좋습니다.

다섯 가지 프로필의 차이#

프로필설정 ID주요 설정과 용도
Token SaversaverSonnet, 낮은 추론 강도, 짧은 답변, Haiku 서브에이전트 설정을 조합합니다. 토큰 사용을 줄이는 방향으로 반복 작업을 진행할 때 검토할 만합니다.
Fast FlowflowSonnet과 중간 추론 강도를 사용하고 파일 수정의 승인 절차를 줄입니다. 사람이 결과를 확인하며 작은 수정을 이어 가는 작업에 어울립니다.
Max Qualityquality사용 가능한 가장 성능 높은 모델과 xhigh 추론 강도를 선택하고 큰 워크플로를 허용합니다. 복잡한 분석이나 리팩토링을 충분히 검토하고 싶을 때 선택할 수 있습니다.
Guardedguarded기본 승인 모드와 우회 모드 제한, 일부 경로의 파일 읽기 제한을 설정합니다. 변경 과정에 사람이 더 자주 개입하려는 작업에 맞습니다.
Autopilotautopilot자동 승인 모드와 높은 추론 강도, 작업 요약, 푸시 알림, 자동 컨텍스트 압축을 켭니다. 승인으로 인한 중단을 줄이며 긴 작업을 진행하는 방향입니다.

서브에이전트 는 일부 작업을 나누어 맡는 별도의 에이전트를 뜻합니다. Token Saver는 이들이 사용할 모델을 Haiku로 지정하는 설정을 포함합니다. 다만 제작자는 이 환경 변수만으로 내장 Explore·Plan 에이전트의 모델까지 모두 바뀌지는 않는다고 설명합니다. 프로필의 이름이 실제 모든 호출의 모델이나 비용을 보장하는 것은 아닙니다.

자동 승인도 프로필마다 범위가 다릅니다. Fast Flow는 파일 수정에 대한 승인 절차를 줄이는 설정이고 Autopilot은 자동 승인 모드를 선택합니다. Autopilot이라는 이름만으로 작업이 끝날 때까지 사람의 판단이 전혀 필요 없다고 가정해서는 안 됩니다.

설치하고 첫 프로필 적용하기#

현재 README는 Claude Code 2.1.287 이상 과 신뢰된 프로젝트 폴더를 요구합니다. 설치 전 버전을 확인한 뒤 작업할 프로젝트에서 아래 명령을 실행합니다.

npx claude-code-templates@latest --mod productivity/ultra-config

설치 후 Claude Code 안에서 다음 명령을 입력하면 설정 패널이 열립니다.

/ultra-config

패널에서 프로필을 고르면 변경할 설정이 펼쳐집니다. 기존 값과 새 값, 이미 적용된 항목, 건너뛰는 항목을 확인한 뒤 Activate를 누릅니다.

처음에는 Token Saver나 Max Quality처럼 목적이 분명한 프로필 하나를 골라 현재 설정과 비교해 보면 이해하기 쉽습니다. 바로 적용하기 전에 Token Saver를 살펴보고 싶다면 다음처럼 해당 프로필의 화면을 열 수도 있습니다.

/ultra-config saver

이 명령은 프로필 화면을 여는 동작입니다. 실제로 활성화하는 명령과 구분해서 사용합니다.

적용·되돌리기·닫기 명령 구분하기#

명령동작
/ultra-config설정 패널을 엽니다.
/ultra-config <profile>지정한 프로필의 상세 화면을 엽니다.
/ultra-config apply <profile>프로필을 적용하고 변경·건너뛰기 항목을 표시합니다.
/ultra-config undo마지막으로 적용한 프로필의 변경을 되돌립니다.
/ultra-config close설정 패널을 닫습니다.

<profile>에는 앞선 표의 설정 ID를 넣습니다. 예를 들어 Max Quality를 바로 적용하는 명령은 다음과 같습니다.

/ultra-config apply quality

적용을 취소하려면 다음 명령을 사용합니다.

/ultra-config undo

패널을 닫는 close는 설정을 되돌리는 명령이 아닙니다. 원래 상태로 돌아가려면 undo를 사용해야 합니다. 또 프로필은 자신에게 지정된 설정 항목을 바꾸는 방식이므로, 다른 프로필로 전환하는 것과 이전 변경을 되돌리는 일을 구분하는 편이 좋습니다.

프로젝트는 최근 적용 이력을 저장해 재시작 후에도 되돌릴 수 있도록 구성되어 있습니다. 기존에 사용자가 추가해 둔 읽기 제한 규칙 등은 되돌리기 과정에서도 보존한다고 설명합니다.

세션 중 전환해도 적용 시점은 설정마다 다릅니다#

기존 세션 안에서 프로필을 선택할 수 있지만 선택한 순간 모든 설정이 함께 바뀌는 것은 아닙니다. README는 적용 시점을 다음과 같이 구분합니다.

설정 종류적용 시점
/config 메뉴에서 다루는 모델·승인 모드·출력 방식 등설정을 변경하면 바로 반영
모델의 추론 강도다음 메시지의 요청부터 적용
CLAUDE_CODE_SUBAGENT_MODEL, MAX_MCP_OUTPUT_TOKENS 환경 변수Claude Code가 시작할 때 읽으므로 다음 세션부터 적용하는 것으로 안내

예를 들어 Token Saver를 활성화한 뒤에도 이미 실행 중인 세션에서 서브에이전트 모델이 곧바로 바뀐다고 기대하면 실제 동작과 차이가 날 수 있습니다. 현재 모델과 추론 강도, 적용 결과를 확인하고 시작 시 읽는 환경 변수의 변경은 새 세션에서 확인하는 것이 좋습니다.

조직에서 잠근 항목이나 현재 Claude Code 버전이 제공하지 않는 설정은 건너뛸 수 있습니다. 패널에 프로필이 보인다는 사실과 그 프로필의 설정이 모두 적용되었다는 사실도 구분해야 합니다. 적용 결과의 변경·유지·건너뛰기 표시를 함께 살펴보면 됩니다.

Guarded가 제한하는 범위도 확인하기#

Guarded는 .env, secrets/, ~/.ssh, ~/.aws 같은 경로에 Read 도구의 읽기 제한을 추가하고 권한 우회 모드를 비활성화합니다. 여기서 Read는 Claude Code가 파일을 읽을 때 쓰는 도구를 뜻합니다.

제작자의 설명 은 이 제한이 셸 명령을 통한 같은 파일의 읽기까지 막는 것은 아니라고 명시합니다. Guarded를 선택했다고 비밀정보 접근을 모든 경로에서 차단하는 격리 환경이 생기는 것은 아닙니다. 기존 글의 “비밀정보 접근을 제한한다”는 설명은 이 도구별 범위까지 포함해 이해해야 합니다.

Ultra Config는 이미 제공되는 설정을 작업 목적에 맞춰 빠르게 바꾸고 변경 내용을 확인하려는 사람에게 유용한 도구입니다. 처음에는 자주 하는 작업 하나를 정한 뒤 변경 예고를 읽고 적용해 보면서 필요한 경우 undo로 돌아오는 흐름부터 익히면 됩니다.
