말하는 음성 비서와 뒤에서 일하는 AI 봇 팀, Thursday 살펴보기

10월 2, 2026 · 6 분 · Junho Lee
원문 webpage
  • github.com/cgoinglove/thursday-agent
목차
  • 핵심 구조와 작동 방식
  • 보안 한계와 사용 시 주의점

Thursday는 개인 컴퓨터에서 돌아가는 음성 비서입니다. 사용자는 말로 대화하고, 시간이 걸리는 일은 뒤에서 여러 AI 봇이 대신 처리합니다. 약 4주 된 신생 프로젝트이지만 코드는 약 11.8만 줄이고, 문서와 테스트, 보안 설명이 이 단계 치고는 꽤 잘 갖춰져 있습니다. 1. 기본 정보 | 항목 | 내용 | |—|—| | 한 줄 소개 | GPT-Live 1 기반 오픈소스 음성 비서 + 뒤에서 일하는 AI 봇 팀 | | 설치·실행 | npx thursday-agent (Node 22.18 이상) | | 라이선스 | MIT | | 버전 | 0.27.0, 0.28.0 출시 PR이 열려 있음 | | 개발 기간 | 2026-09-08 생성, 마지막 푸시 10-01. 9월 한 달에만 출시 31번 | | 규모 | TS/TSX 약 11.8만 줄. 그중 테스트 스크립트가 약 2.2만 줄 | | 인기 | ⭐ 25, 포크 3, 열린 이슈·PR 9개 | | 개발 대상 OS | macOS (리눅스는 “될 것”, 윈도우는 아직 테스트 안 함) | 2. 핵심 구조: 말하는 모델과 일하는 봇의 분리 음성 모델이 브라우저 작업까지 직접 하면 그동안 1분 넘게 말이 없어집니다. 개발자는 이를 “조용한 통화는 죽은 통화"라고 표현합니다. 그래서 역할을 세 단계로 나눴습니다. 출처 | 계층 | 담당 | 하는 일 | |—|—|—| | ① 음성 | GPT-Live 1 | 통화 유지. 사용자가 중간에 끊거나 말을 바꿔도 대응 | | ② 백엔드 | Responses 모델 (기본값 “GPT-6 Luna”) | 생각하고 도구 사용. 메모리 읽기/쓰기, 셸 명령 1개 같은 빠른 일만 직접 처리 | | ③ 봇 | OpenAI·Anthropic·Google·xAI 등 텍스트 모델 | 셸, 실제 브라우저, 파일, 스킬, MCP 서버, 이미지·영상 생성 도구로 오래 걸리는 작업 수행 | - 작업은 통화가 끝나도 계속됩니다. 작업은 로컬 서버에서 돌고, 모든 단계가 DB에 저장됩니다. 그래서 질문 때문에 멈춘 작업도 나중에 그 지점부터 이어서 진행됩니다. - 봇끼리 일을 나눕니다. 작업을 받은 봇이 다른 봇에게 일부를 맡기고, 결과를 기다렸다가 검토합니다. 사용자가 정해야 하는 것만 사용자에게 묻습니다. - 결제 직전에 멈춥니다. 구매는 결제 버튼 바로 앞 화면을 열어 둔 채로 멈추고, 버튼은 사용자가 누릅니다. - 봇이 배운 것을 기록합니다. 작업이 끝나면 각 봇이 한 번 돌아보고, 일하는 방법에 대해 배운 것을 자기 메모리 파일에 남깁니다(v0.27 신기능). - 휴대폰이나 이메일로도 지시할 수 있습니다. 텔레그램, 디스코드, 슬랙, 이메일을 지원합니다. 앱이 바깥으로 연결하는 방식이라 내 컴퓨터의 포트를 인터넷에 열 필요가 없습니다. - 정해진 시간에 작업을 시작합니다. 예: “평일 9시마다 메일을 정리하고 답장 초안 작성”. 출처 3. 기술 스택 - 프레임워크: Next.js 16, React 19, Tailwind 4, shadcn - AI: Vercel AI SDK v7. Anthropic, Google, xAI, Groq, DeepSeek, Mistral, OpenRouter 등 10개가 넘는 제공자 지원. MCP 연동 - 데이터: SQLite(libsql)와 Drizzle ORM 1.0 rc. 마이그레이션 16개 - 브라우저 자동화: @playwright/cli. 봇 전용 브라우저를 쓰거나, 사용자의 Chrome에 붙어서 작업 - 메일: imapflow, nodemailer, mailauth(DKIM/DMARC 검증) - 실시간 음성: WebRTC (lib/live/live.transport.ts) - 품질 관리: Biome, knip, TypeScript 타입 검사, Node 내장 테스트 러너, release-please. CI는 Node 최신 버전과 22.18 두 가지로 돌림 4. 코드가 어디에 많은가 | 영역 | 줄 수 | 내용 | |—|—|—| | features/bot | 약 24,000 | 봇 실행, 작업 기록, 봇끼리의 대화방, 사무실 애니메이션 (office.scene.ts만 2,286줄) | | scripts (테스트) | 약 21,600 | 영역별 테스트 묶음 8개, 제공자는 모두 가짜(mock)로 처리 | | features/thursday | 약 19,400 | 통화 화면, 얼굴 표정과 눈 애니메이션, 위치와 날씨 반영 | | features/ai | 약 10,000 | 프롬프트, 도구 16개(봇, 메모리, 정기 작업, 로그인, 스튜디오, 슬라이드 등), 모델 선택 | | features/reach | 약 5,800 | 휴대폰·이메일 채널 | | skills/ | 파일 258개 | 기본 제공 스킬: browser, artifact, data-report, interactive-page, daily-brief 등 | 해석: 화면과 연출(얼굴, 사무실 애니메이션)에 들어간 코드가 아주 많습니다. “작업 과정을 사무실처럼 보여주는” 사용 경험을 차별점으로 밀고 있다는 뜻입니다. 5. 눈에 띄는 장점 1. AI 코딩 에이전트용 규칙이 잘 정리돼 있습니다. AGENTS.md와 .claude/rules/에 영역별 안내 문서가 12개 있습니다. 그 문서들이 실제 코드와 어긋나지 않는지 pnpm lint가 검사합니다. “모델이 할 판단을 휴리스틱으로 대신하지 않는다”, “실패를 감추는 재시도나 대체 동작 금지” 같은 원칙도 명시돼 있습니다. 2. 보안 한계를 숨기지 않고 적어 둡니다. SECURITY.md에 막아 둔 것과 못 막는 것이 구분돼 있습니다. - 막아 둔 것: 저장된 키를 AES-256-GCM으로 암호화, 셸 환경에서 KEY|TOKEN|SECRET…이 들어간 환경 변수 제거, 서버는 127.0.0.1에서만 열림 - 못 막는 것: 셸은 사용자 권한으로 어디든 쓸 수 있음. 암호화 키도 같은 폴더의 .env에 있어서 봇 셸이 읽을 수 있음 3. 데이터가 로컬에 남습니다. DB, 메모리, 결과 파일은 모두 ~/.thursday에 있습니다. 메모리는 사용자가 직접 읽고 고칠 수 있는 평문 메모입니다. 4. 설치가 쉽습니다. .env 설정 없이 첫 화면에서 ChatGPT 로그인이나 OpenAI 키만 입력하면 됩니다. 6. 위험 요소와 한계 | 구분 | 내용 | |—|—| | ⚠️ 샌드박스 없음 | 봇이 사용자 권한으로 실제 명령을 실행합니다. “결제 금지"는 모델이 지시를 따르는 것일 뿐, 코드로 막혀 있지 않습니다 | | ⚠️ 내 Chrome 통째 대여 | 봇이 사용자 Chrome에 붙으면 그 브라우저에 로그인된 모든 사이트에서 작업할 수 있고, 붙기 전에 따로 묻지 않습니다 | | ⚠️ ChatGPT 로그인 방식 | Codex CLI의 OAuth 클라이언트를 빌려 로그인합니다. 규칙 문서에도 “유일한 예외이자 관리자의 선택"이라고 적혀 있어, OpenAI 정책이 바뀌면 깨질 수 있습니다 | | 모델이 로컬이 아님 | 음성은 OpenAI로 전송됩니다. 로컬 모델 지원은 이슈 #16으로 열려 있습니다 | | 사실상 1인 개발 | 열린 항목 중 외부 기여는 터키어 지원(#69, #70) 정도입니다. 아직 초기 단계라 변경 속도가 빠르고 바뀔 가능성이 큽니다 | | 플랫폼 | 윈도우 미지원(#17). 화면은 영어 전용이고, 음성은 사용자 언어로 말합니다 | 결론 - 써볼 만한 경우: “음성으로 지시하고 여러 에이전트가 처리하는” 구조를 연구하거나, 로컬에서 자동화 비서를 실험해 보려는 경우입니다. 음성과 백엔드를 나눈 설계, 통화가 끝나도 이어지는 작업, 봇끼리 일을 넘기는 구조는 참고할 가치가 높습니다. - 조심할 경우: 중요한 계정이 로그인된 메인 Chrome이나 업무용 컴퓨터에 바로 붙이는 것은 권하지 않습니다. 별도 사용자 계정이나 가상 머신에서 쓰는 편이 안전합니다.

개인 컴퓨터에서 음성으로 대화하며 뒤에서 여러 AI 봇이 실무를 처리하는 오픈소스 음성 비서 Thursday가 공개되었습니다. 약 4주 동안 빠른 속도로 개발된 프로젝트로, 음성 모델과 백엔드 봇을 분리해 끊김 없는 대화를 지원합니다.

음성 모델이 브라우저 자동화 같은 무거운 작업을 직접 처리하면 수십 초 동안 대화가 멈추는 현상이 발생합니다. 프로젝트 개발자는 이를 방지하려고 역할을 세 단계로 나누었습니다. 실시간 음성을 담당하는 음성 모델과 빠른 응답을 처리하는 백엔드 모델, 그리고 실제 셸이나 브라우저 작업을 수행하는 텍스트 봇 팀이 협력하는 구조입니다.

핵심 구조와 작동 방식#

작업은 통화가 끝난 뒤에도 로컬 서버에서 계속 실행되며 모든 단계가 데이터베이스에 기록됩니다. 작업을 위임받은 봇은 다른 봇에게 업무를 나누고 결과를 기다렸다가 검토합니다. 구매 작업의 경우 결제 버튼 바로 전 단계에서 멈추어 사용자가 직접 최종 승인을 내리도록 설계되었습니다.

실행 환경과 기술 스택도 다양하게 갖춰져 있습니다. Next.js 16과 React 19를 바탕으로 Vercel AI SDK를 활용하며, SQLite와 Drizzle ORM을 통해 데이터를 로컬에 저장합니다. 사용자는 터미널에서 npx thursday-agent 명령어로 쉽게 실행합니다.

보안 한계와 사용 시 주의점#

로컬 환경에서 작동하지만 몇 가지 주의할 점이 있습니다. 샌드박스 없이 사용자 권한으로 셸 명령을 실행하기 때문에 업무용 PC보다는 별도 환경에서 테스트하는 편이 안전합니다. 또한 사용자의 브라우저 세션에 바로 붙어 작업을 수행하므로 권한 관리에 유의해야 합니다.

음성으로 지시하고 여러 에이전트가 협업하는 구조를 연구하려는 엔지니어에게 흥미로운 참고 사례가 됩니다.

요약#

  • 음성 모델과 백엔드 작업을 분리해 대화 지연을 방지합니다.
  • 작업 이력이 데이터베이스에 저장되어 중단된 지점부터 이어서 진행할 수 있습니다.
  • 실제 브라우저와 셸을 조작하므로 보안과 권한 관리에 주의가 필요합니다.
