Claude Code 비용을 줄이려면: 작업 반복과 입력 재사용부터 보세요

Claude Code로 기능을 만들 때 드는 비용은 가격표만 보고 알기 어렵습니다. 코드를 읽고, 고치고, 테스트 결과를 다시 읽는 과정에서 입력과 출력이 계속 쌓이기 때문입니다. 이 글은 Opus 5.5의 원문 가격 예시를 바탕으로, 작업을 반복한 횟수와 입력 재사용 여부가 비용을 어떻게 바꾸는지 설명합니다.

한눈에 보기#

  • Opus 5.5는 Opus 5보다 API 정가 기준으로 입력·출력 토큰이 20%, 캐시 읽기가 60% 쌉니다.
  • 토큰 수를 똑같이 두고 계산한 예시 세션은 $3.50에서 $2.40으로, 약 31% 줄어듭니다.
  • 모델이 작업을 반복하는 턴 수, 같은 입력을 재사용하는 캐시 적중률, 답변과 추론에 쓰는 출력 토큰이 작업 비용을 크게 좌우합니다.
  • 가장 믿을 만한 숫자는 내 작업을 두 모델에 돌리고 /usage 로 비교한 값입니다.

원문 소개#

Addy Osmani가 2026년 9월 25일에 claude.dev 블로그에 올린 글입니다. Claude Code를 API 키로 쓰거나 팀의 사용량을 관리해야 하는 개발자에게 맞습니다. 글 속 숫자는 정가와 거기서 만든 예시이므로 본인 계산으로 다시 확인하라고 저자도 당부합니다.

작업 하나의 비용은 무엇이 정할까#

먼저 토큰은 모델이 읽고 생성하는 텍스트를 세는 단위입니다. 모델에 보내는 요청과 코드, 도구 실행 결과는 입력이고 모델이 생성한 답변과 추론 내용은 출력으로 계산합니다.

Claude Code는 대화를 읽고 도구를 호출하고 그 결과를 읽는 일을 반복합니다. 예를 들어 코드를 읽은 뒤 수정하고 테스트를 실행한 뒤 실패한 부분을 다시 고치는 식입니다. 원문은 이 반복의 한 바퀴를 턴으로 설명합니다. 매 턴에는 지금까지 쌓인 대화 전체를 다시 보내므로, 대화가 길어질수록 입력도 커집니다.

대화 전체를 다시 보내더라도 모든 입력을 매번 새 입력의 가격으로 계산하는 것은 아닙니다. 동일한 앞부분을 재사용하는 프롬프트 캐시가 있으면 그 부분은 더 낮은 캐시 읽기 가격을 적용합니다. 캐시 적중률은 전체 입력 중 이렇게 재사용한 비율입니다. 이 차이를 포함해 비용을 정하는 요소는 네 가지입니다. 아래에서 K는 천, M은 백만 토큰 단위입니다.

  • 턴 수: 모델이 한 번에 참고하는 대화와 자료인 컨텍스트가 20K에서 120K까지 자라는 작업을 40턴 실행하면 입력 합계는 약 2.8M 토큰입니다. 90%를 캐시에서 읽으면 입력비는 약 $1.62입니다. 같은 조건에서 작업을 25턴에 끝내는 예시는 약 $1.02입니다. 덜 반복하면 긴 대화를 다시 보내는 횟수도 줄어듭니다.
  • 캐시 읽기: 같은 2.8M 토큰도 캐시가 없으면 $11.20, 적중률 96%면 약 $0.99입니다. 이 예시에서 입력비 차이가 큰 이유는 대부분을 더 싼 재사용 가격으로 읽기 때문입니다.
  • 출력 토큰: Opus 5.5에서 출력 토큰 단가는 캐시 읽기 단가의 100배입니다. 출력 60K의 비용 $1.20은 캐시 6M 토큰을 읽는 비용과 같습니다. 모델의 추론인 thinking도 출력에 포함되므로, 계산 자원 사용 수준을 정하는 effort를 올리면 이 항목도 늘 수 있습니다.
  • 모델: 선택한 모델에 따라 입력, 출력, 캐시 각각의 단가가 달라집니다.

계산 기준은 원문에 나온 Opus 5.5의 API 정가로, 100만 토큰당 입력 $4, 출력 $20, 캐시 읽기 $0.20입니다. 예시들은 캐시에 내용을 처음 저장하는 쓰기 비용을 뺀 계산입니다. 전체 청구액을 계산할 때는 그 비용도 따로 봐야 합니다.

불필요한 반복을 줄이려면 모델이 결과를 확인할 수 있는 테스트나 빌드 명령을 알려 줍니다. 테스트 실패 결과가 있으면 무엇이 틀렸는지 구체적으로 확인하며 고칠 수 있습니다.

Opus 5.5에서 바뀐 것#

첫째는 가격입니다. 캐시 읽기 가격이 입력가의 10분의 1에서 20분의 1로 내려갔습니다. 원문은 Pro, Max, Team 구독 플랜에서 같은 한도로 Opus 5보다 약 25% 더 많은 작업을 처리할 수 있고, 5시간 한도도 올랐다고 설명합니다. 구독의 사용 한도와 API의 달러 청구액은 구분해서 읽어야 합니다.

API 키로 쓰는 긴 에이전트 세션에서는 반복 입력의 많은 부분이 캐시 읽기이므로 이 가격 인하가 크게 작용합니다. 원문의 예시 세션을 같은 토큰 수로 두 모델에 적용하면 캐시 읽기 항목이 $1.00에서 $0.40으로 내려갑니다.

그림 1. 100만 토큰당 API 정가입니다. Input은 입력, Output은 출력, Cache read는 캐시 읽기입니다. 입력·출력은 20%, 캐시 읽기는 60% 낮아졌습니다. 출처: 원문 .

예시 세션의 항목Opus 5Opus 5.5
캐시 읽기$1.00$0.40
신규 입력$1.00$0.80
출력$1.50$1.20
합계$3.50$2.40

위 표의 Opus 5.5 비용은 원문이 준 캐시 읽기 $0.40, 합계 $2.40과 단가로 계산한 값입니다. 계산은 사용량에 해당 단가를 곱하면 됩니다.

  • 신규 입력: 200K × $4/M = $0.80
  • 출력: 60K × $20/M = $1.20
  • 합계: $0.40 + $0.80 + $1.20 = $2.40

합계 차이는 ($3.50 − $2.40) ÷ $3.50 ≈ 31%입니다. 토큰 수를 똑같이 두었으니 가격 인하만 반영한 비교입니다. 모델이 일을 더 적게 반복해서 생길 절감은 포함하지 않았습니다. 가장 크게 줄어든 항목은 캐시 읽기이고 출력 비용도 줄었지만 여전히 가장 비싼 항목입니다.

둘째는 일하는 양입니다. 흔히 들리는 “40% 저렴하다"는 Anthropic이 기본 설정의 일반 작업을 가정해 낸 추정치입니다. 토큰 단가가 40% 내렸다는 뜻은 아닙니다. Opus 5.5가 토큰을 덜 쓴다는 가정이 들어 있습니다. 범위가 분명한 작업은 두 모델의 턴 수가 비슷해서 가격 인하분만큼만 아낍니다. 탐색 범위가 넓고 시행착오가 생기기 쉬운 개방형 작업에서는 차이가 더 벌어질 것이라고 합니다.

세션을 운영하는 요령#

막히면 검증 수단부터 확인하기#

effort는 모델이 작업에 얼마나 많은 계산 자원을 쓸지 알려 주는 설정입니다. low, medium, high, xhigh 네 단계에 한 세션용 max가 있습니다. 원문에서 Opus 5.5의 기본값은 medium입니다(Opus 5는 high). 같은 단계라도 Opus 5.5가 더 많이 생각하므로 Opus 5의 설정을 그대로 옮기지 말라고 합니다.

effort를 높이면 비용이 늘어도 재시도를 줄여 전체 비용은 낮아질 수 있습니다. 원문의 예시에서 high가 thinking 20K를 더하면 $0.40입니다. 캐시된 컨텍스트 100K로 열 턴을 반복하고 출력이 합쳐 10K인 재시도 한 묶음도 비용이 비슷합니다. 계산은 1M × $0.20/M + 10K × $20/M = $0.40입니다. 이 정도의 재시도를 막는다면 추가 추론 비용을 회수한다는 뜻입니다.

그래서 원문은 먼저 테스트나 빌드로 결과를 확인할 수 있는지 보고, 그래도 막히면 effort를 높이고 마지막으로 모델을 바꾸라고 권합니다.

모델을 바꿀 때의 기준#

저자는 사람이 직접 지켜보는 일에 Opus 5.5를 씁니다. 지켜보지 않는 긴 작업이나 선례 없는 문제에는 Fable 5.1을 권합니다. Fable 5.1의 가격은 100만 토큰당 입력 $10, 출력 $50, 캐시 읽기 $0.25입니다. 검색이나 로그 읽기를 나눠 맡는 보조 AI인 서브에이전트에는 Sonnet이나 Haiku를 씁니다. xhigh에서 같은 문제에 두 번 막히면 Fable 5.1로 옮기고, 해결한 뒤에는 돌아오라는 기준입니다.

원문은 effort를 올리는 쪽이 큰 모델로 옮기는 것보다 덜 든다고 합니다. 그래서 앞 단계에서 풀리면 거기서 멈추는 편이 쌉니다.

캐시가 유지되도록 세션 다루기#

캐시는 요청의 앞부분이 같을 때 재사용됩니다. 앞서 보낸 지침과 대화는 그대로 두고 새 내용을 뒤에 덧붙이면 기존 부분을 읽기 가격으로 처리할 수 있습니다. 읽기는 신규 입력 가격의 5%입니다. 반면 캐시에 처음 저장하는 쓰기는 5분 캐시가 신규 입력 가격의 1.25배, 1시간 캐시가 2배입니다. 120K 컨텍스트를 읽는 비용은 약 $0.02지만, 5분 캐시에 쓰는 비용은 약 $0.60입니다.

원문에서 구독의 캐시 수명은 1시간(사용량 크레딧을 쓰는 중에는 5분), API 키는 기본 5분입니다. 수명보다 오래 쉬면 캐시가 만료됩니다. 모델을 바꾸거나 외부 도구를 연결하는 MCP 서버를 붙이거나, 대화를 요약하는 /compact를 실행해도 쓰기 비용이 다시 나갑니다.

/compact는 긴 대화를 짧게 요약해 이후에 보내는 입력을 줄이는 명령입니다. 캐시가 유지되는 상태에서 150K 지점에 실행하면 약 $0.25입니다. 이후 턴마다 읽기 비용이 약 $0.025 줄어 약 열 턴 안에 회수됩니다. 5분 캐시가 만료된 뒤 실행하면 입력만 약 $0.75이므로, 원문은 이 예시에서 쉬기 전에 요약하라고 권합니다.

시작할 때 설정을 정해 두고 작업 중에는 건드리지 않는 편이 쌉니다.

인사이트#

이 부분은 원문이 아니라 이 블로그의 해석입니다.

  1. 비용을 줄이려면 총액과 함께 어디에 많이 썼는지 살펴봐야 합니다. /usage에서 캐시 비율을 보면 이전 입력을 얼마나 재사용했는지 알 수 있습니다. 출력량을 입력량과 비교하면 답변과 추론을 얼마나 많이 생성했는지, 누적 입력량을 대화 크기와 비교하면 같은 내용을 얼마나 반복해서 보냈는지 짐작할 수 있습니다. 직접 에이전트를 만든다면 이런 값을 실행 기록에 남겨 비용이 커진 이유를 찾아볼 수 있습니다.

  2. 결과를 확인할 도구가 있으면 틀린 답을 찾고 불필요한 재시도를 줄이는 데 도움이 될 수 있습니다. 예를 들어 데이터를 처리하는 에이전트에 데이터베이스 조회문인 SQL이 실제 데이터 구조와 맞는지 검사하는 도구를 붙이는 방식입니다. 작업이 막힐 때는 더 비싼 모델로 바꾸기 전에 에이전트가 스스로 오류를 확인할 방법이 있는지 살펴볼 만합니다.

  3. 공통 지침과 사용할 도구는 작업을 시작할 때 정해 두는 편이 좋겠습니다. 같은 입력을 재사용하는 캐시는 요청 앞부분이 유지될 때 활용하기 쉽기 때문입니다. 작업 중 새로 생긴 요청과 결과는 기존 내용을 자주 바꾸기보다 뒤에 덧붙이는 방식이 비용 관리에도 도움이 될 것으로 보입니다.

바로 해볼 것#

  • claude update로 업데이트한 뒤 v2.1.280 이상인지 확인합니다. 실제 작업 하나를 같은 요구사항으로 Opus 5와 Opus 5.5에 각각 맡기고 결과의 품질과 함께 작업을 반복한 횟수인 턴, 출력 토큰, 비용을 비교합니다.
  • /effort status로 현재 effort 단계를 확인합니다. 해야 할 일이 분명한 작업은 medium에서 시작하고 테스트 결과를 보며 더 높은 설정이 필요한지 판단합니다.
  • /mcp로 Claude Code에 연결된 외부 도구 서버를 확인합니다. 이번 작업에 필요한 도구가 무엇인지 살펴보고 사용하지 않는 서버는 작업을 시작하기 전에 꺼 둡니다.
